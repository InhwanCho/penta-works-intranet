# 입출금 집행 확인

## 사용 흐름

회계 → 입출금 확인(`/accounting/review`)에서 계획 기준월을 선택한다. 이전 달 미완료 계획도 함께 조회한다. 은행거래와 입출금 계획에서는 확인 메뉴로 이동한다.

적요와 거래처 텍스트를 계획의 검색어와 대조한다. 검색어가 없으면 거래처명·계획명(숫자/회차 제거)과 건강보험·국민연금·고용보험·산재보험 명칭을 사용한다. 공백·문장부호·대소문자는 무시하고 두 글자 이상만 비교한다. 사용자가 쉼표로 여러 별칭을 지정할 수 있다. 자동 탐색은 읽기 전용이며 거래를 선점하거나 완료 처리하지 않는다. 같은 거래가 여러 계획의 후보일 수 있으므로 담당자가 선택한다.

날짜 기본값은 예정일 전후 7일(달력일), 계획별 0~14일 설정 가능. 월말과 월초를 넘어서 탐색한다. 개별 검토에서 최대 200일을 직접 조회할 수 있다. 후보 순서는 적요+날짜+금액 정상 범위, 그 밖의 적요 일치, 직접 확인 순이다. 금액 정상 범위는 누적 실제 집행액이 예산의 80~120%이거나 예산과의 절대 차액이 10,000원 이하인 경우이며 경계값을 포함한다. 즉, 허용 차액은 max(예산×20%, 10,000원)이다. 정상 범위를 벗어난 거래도 표시하고, 메모를 입력하면 수동 완료할 수 있다. 금액 미정 계획 역시 거래 연결 및 사유 입력 후 완료할 수 있다.

담당자는 실제 거래를 선택한 뒤 `최종 집행 완료` 또는 `일부 집행 / 반환 저장`을 누른다. 완료 시 예산 금액을 변경하지 않고 잔여 계획만 0으로 처리한다. 통장 실적은 원래 금액을 그대로 유지한다. 단순히 계획금액을 채운 것만으로는 자동 완료되지 않는다.

## 예외

- 분할: 여러 실제 거래를 하나의 계획에 연결한다. 완료하지 않고 일부 집행으로 저장할 수 있다.
- 합산: 실제 거래의 반영 금액을 줄여 여러 계획에 나누어 연결한다. 남은 미배분액을 다시 조회할 수 있다.
- 미연결: 선택 월에 계획이 없거나 일부만 배분된 은행거래를 별도로 보여준다. 기존 계획에서 직접 연결하거나 계획 등록으로 이동한다. 내부이체는 제외한다.
- 반환: 반대 방향의 거래를 수동 연결하면 음수 배분으로 실제 집행액에서 차감한다. 완료를 해제한 뒤 반환을 연결한다. 반환이 연결된 원거래는 반환부터 해제해야 한다. 반환 후 총 집행액이 0이면 완료할 수 없다. 완료 계획도 적요가 일치하는 반환 후보가 탐색 범위 안에서 발견되면 확인 대기 목록에 다시 표시된다. 범위 밖 반환은 미연결 목록/수동 날짜 확장에서 확인한다.
- 미수집: 예정일+탐색일이 지나도 `거래 미확인`으로 표시한다. 자동으로 미집행을 확정하지 않는다. 계좌별 마지막 수집 시각과 오류를 함께 제공한다. 마지막 수집 시각은 모든 날짜의 완전한 수집을 보증하지 않는다.

확정·일부 저장·규칙 수정·연결 해제에 버전 검사와 감사 이력을 적용한다. 원거래의 총 배분 한도는 양수/음수 배분의 절댓값 합으로 검사한다. 동시 요청은 계획/은행거래 잠금으로 직렬화한다. 취소된 계획에는 집행을 연결할 수 없다.

## 스키마와 호환

`028_cash_execution.sql`을 배포 시 적용한다. 기존 정확한 금액으로 확정 연결된 계획은 완료로 이관한다. 신규/변경 계획은 명시적인 수동 확정이 필요하다. 기존 계획이 가진 최초 금액·날짜와 실제 거래는 보존한다. 계획을 수정하거나 거래 연결을 해제하면 다시 확인해야 한다.

규칙은 개별 계획에 저장된다. 반복 그룹 전체 일괄 규칙 변경, 검색어 학습, 대량 일괄 확정은 이번 범위에 포함하지 않는다.


## 확인 작업을 한 메뉴로 통합

실제 거래 연결·분할 배분·완료·반환·연결 해제·완료 해제·계획 없는 거래 확인은 `/accounting/review`에서만 제공한다. 대시보드·자금달력·일별집계·계획·카드 결제예정·은행거래는 확인 상태를 조회하고, 계획 화면은 등록·수정만 담당한다. 은행거래와 계획 화면에는 확인 메뉴로 이동하는 안내만 제공한다.

확인 메뉴에는 세 가지 탭이 있다.

- 확인할 계획: 예정일/금액/계좌와 추천 거래의 일시/금액/적요/계좌를 나란히 비교한다. 추천이 있는 계획부터 표시한다. 한 건만 추천되고 조회된 다른 계획의 후보와 중복되지 않을 때에만 거래를 미리 선택하며, 최종 완료는 담당자가 누른다. 여러 후보·중복 후보는 직접 선택한다.
- 미연결 거래: 기존 계획을 찾아 연결하거나 계획 없는 거래로 사유를 남겨 확인한다. 일부 배분 거래는 잔여 금액을 표시한다.
- 완료 내역: 완료 계획과 계획 없이 확인한 거래를 조회하고 재검토·확인 해제할 수 있다. 확인 취소 기능을 은행거래 화면에 남겨두지 않는다.

일반 확인에서는 추천 거래와 완료 버튼을 우선 보여준다. 다른 날짜/적요 검색, 분할·합산·반환 처리, 메모, 자동 식별 규칙은 필요할 때 펼친다. 금액을 나눈 상태로 일반 확인에 돌아가도 입력한 배분액은 유지한다.

은행거래 목록의 원본 거래번호는 화면에서 숨기고 확인 상태만 표시한다. 전체 금액이 배분되고 모든 연결 계획이 완료되어야 확인 완료다. 내부이체는 별도로 표시한다. 원본 거래번호는 DB에 보존한다.

계획 없는 거래는 사유를 남겨 확인할 수 있다. 이 동작은 계획을 생성하거나 다른 계획을 완료하지 않는다. 확인 해제 전까지 계획 배분 및 내부이체에 재사용할 수 없다. 버전·금액 검사와 감사 기록을 유지한다. 저장 스키마는 `029_bank_review.sql`을 그대로 사용하며 이번 화면 통합에 새 마이그레이션은 없다.

## 일별 집계

일자·은행 열을 두고 은행별 행과 하루 합계로 구성한다. 같은 은행의 여러 계좌는 합산한다. 기타 은행과 계좌 미지정 계획도 표시한다. 출금계획은 일반·카드 계획의 합계이며 카드액을 보조 표시한다. 활동이 없는 날짜는 기본 숨기고 체크박스로 모두 표시한다. 확인 잔액은 구성 계좌 중 하나라도 미확인이면 합계를 미확인으로 표시한다.

## 데스크톱 목록과 미집행 처리

일별 자금집계 메뉴와 전용 화면을 제거했다. 기존 `/accounting/daily` 주소는 입출금 확인으로 이동한다. 입출금 확인은 예정일·계획/계좌·예상금액·추천 거래/실제금액·상태·처리의 단일 표로 표시한다. 단계 안내와 설명 배너, 추천 새로고침 버튼은 제거했다. 월·검색·탭은 유지한다.

미확인 계획은 거래 찾기·연결을 진행하거나, 연결된 금액이 없을 때 미집행 사유와 다음 확인 일정을 메모로 기록할 수 있다. 기존 수동 검토 API와 감사 기록을 사용하며 완료로 처리하지 않는다. 미집행 기록은 `미집행 확인:` 접두어가 있는 검토 메모로 보존한다. 잔여 예산과 추천 대상에 유지하며, 새 거래 후보가 발견되면 다시 추천 표시가 우선한다. 다음 확인 일정은 메모이며 자동 알림·예약 기능은 아니다. 날짜·금액 변경 또는 취소는 계획 메뉴에서 처리한다. 실제 거래가 있지만 계획이 없는 경우는 미연결 거래 탭에서 연결하거나 계획 없는 거래로 확인한다.
