# 회계·자금관리 1차

## 화면과 운영

- `/accounting`: 계좌별 마지막 확인 잔액, 선택 월의 미처리 입출금, 기한 지난 계획, 달력.
- `/accounting/cash`: 월간·주간 달력, 날짜별 계획 및 은행 실적. 실제 거래와 잔여 계획을 분리한다.
- `/accounting/plans`: 계획 등록·수정·취소, 검색, 상태·계좌·방향 필터, 실제 거래의 부분 연결·해제.
- `/accounting/banks`: 기존 API 거래 조회, 계좌 목록 갱신, 선택 계좌·기간 수집, 내부이체 양쪽 거래 연결·해제.
- `/accounting/cards`: 기존 BC·하나 승인내역 XLS/XLSX 업로드, 중복 확인, 업로드 이력 및 복원.
- `/accounting/card-bills`: 카드사별 결제월 합계 직접 등록, 추정/확정 구분, 실제 출금 연결. 승인내역 합계를 청구액으로 자동 전환하지 않는다.
- 기존 세금계산서 기능은 유지한다. 급여·손익 등의 가상 데이터 화면은 메뉴에서 제외한다.

## 저장 및 계산

계획은 기존 `accounting_ledger_entries`, 실적 연결은 기존 `accounting_payment_allocations`를 사용한다. 새 `accounting_cash_plans`는 최초 일정·금액, 거래처 표시명, 분류 표시명, 확정 수준, 카드 결제월을 보관한다. 현재의 거래처·분류 입력은 자유 텍스트이며 정식 거래처원장 연동은 후속 범위다.

반복 등록은 1/3/6/12/24개월을 한 번에 생성한다. 원래 일자를 기준으로 생성하므로 1월 31일 → 2월 28일 → 3월 31일이다. 매월 말일 선택도 가능하다. 상시 자동 생성하는 반복 규칙이나 이후 회차 일괄 수정은 후속 범위이며, 현재는 생성된 개별 건을 수정한다.

잔여 계획은 예정금액에서 확정 연결액을 뺀다. 기한이 지나도 소거하지 않는다. 수정은 최초 계획을 보존하고 버전 검사와 감사 기록을 남긴다. 실제 거래는 여러 계획으로 분할 연결할 수 있지만 거래 금액 및 각 계획 잔여액을 초과할 수 없다. 행 잠금과 READ COMMITTED 트랜잭션으로 동시에 연결해도 초과 배분하지 않는다. 연결된 계획을 취소하거나 연결액보다 적게 수정할 수 없다.

내부이체는 서로 다른 원화 계좌의 출금과 입금을 담당자가 확인해 연결한다. 출금액 = 입금액 + 수수료를 검증하고, 연결된 원금은 외부 자금수지에서 제외한다. 수수료는 외부 출금으로 유지한다. 계획·장부에 이미 연결된 거래는 내부이체로 재사용하지 못한다. 이는 이체 실행 기능이 아니다.

대시보드 잔액은 계좌별 가장 최근 거래후잔액이다. 동시점 실시간 잔액으로 표시하지 않는다. 마지막 거래에 잔액이 없으면 미확인으로 표시하며 임의로 0원을 사용하지 않는다. 카드사별 동일 결제월의 활성 청구 계획은 하나만 허용한다.

## 배포

`database/init/022_cash_planning.sql`을 적용해야 한다. `deploy/deploy.sh`의 기존 마이그레이션 순서에 추가했다. 기존 DB를 사용하는 환경에서는 컨테이너 재시작만으로 init SQL이 적용되지 않으므로 배포 스크립트 또는 별도 마이그레이션 실행이 필요하다. 적용 전에는 신규 계획 기능에 DB 준비 안내를 표시한다. 기존 은행·카드 데이터는 삭제하거나 시드로 대체하지 않는다.

## 검증

- 프런트엔드: `npm run typecheck`, `npm run lint`, `npm run build`.
- 백엔드: Java 17에서 `./gradlew test`.
- 별도 로컬 MariaDB에서 `ACCOUNTING_TEST_DB_URL=jdbc:mariadb://127.0.0.1:<port>/mysql ./gradlew test` 실행 시 반복 날짜, 부분 배분, 동시 배분, 중복 청구, 롤백, 내부이체 수수료·해제 및 접근 권한 검증.
- UI는 테스트 API 응답으로 계획 저장, 부분 거래 연결, 달력 전환, 선택 색상, 모바일·다크모드를 확인한다. 운영 API를 호출하거나 운영 데이터를 변경하는 검증은 아니다.
