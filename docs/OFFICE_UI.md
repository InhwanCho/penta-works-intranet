# Office 화면과 조회 성능 (2026-10-07)

병원 중심의 이동 흐름을 유지하고 회색 배경·흰색 표면·진한 글자·파란색 버튼을 사용한다. 넓은 배경은 중립색으로 유지하고 버튼·링크·선택 표시·아이콘에 파란색을 적용한다.

## 화면 기준

- `frontend/src/app/office-theme.css`에서 색상, 카드, 입력란, 기본/보조/삭제 버튼 크기를 관리한다. 기존 화면별 스타일 뒤에 적용한다.
- 목록·상세·작성 화면의 메뉴 이름, 순서, 아이콘은 `frontend/src/lib/office-navigation.ts`를 함께 사용한다.
- 기본은 라이트 모드다. 기존 버전은 운영체제의 다크 설정도 저장했기 때문에 첫 업데이트에서 테마를 라이트로 한 번 초기화한다. 이후 사용자가 직접 선택한 테마와 큰 글씨 설정은 보존한다.
- 병원 목록에서 이름·지역·주소를 검색한 뒤 장비·부품·서비스 이력으로 이동한다.
- 로그인은 장식이나 홍보 영역 없이 중앙의 단일 폼으로 구성한다. 아이디/비밀번호 자동완성과 비밀번호 표시 토글을 제공하며 로그인 API는 유지한다.
- 기본 본문과 보조 글자의 대비를 높이고, 입력란은 선명한 테두리·포커스 표시를 사용한다. 비활성 로그인 버튼도 흐린 색으로 만들지 않는다.
- 통합 업무 일정의 날짜 칸 디자인은 기존 격자로 유지하며, 날짜를 누르면 해당 일의 일정과 기록을 모달로 보여준다. 닫기 버튼, Esc, 바깥 영역 클릭으로 닫을 수 있고 닫은 뒤 선택한 날짜로 포커스가 돌아간다.
- 대시보드와 병원 상세의 준비물은 실제 체크박스를 사용한다. 미완료는 빈 칸, 완료는 체크 표시로 구분하며 기존 완료 상태 저장 API를 유지한다.
- 사이드바는 루트 레이아웃의 `OfficeFrame`에서 한 번 렌더링한다. 목록·상세·작성 화면이 전환되어도 같은 메뉴를 유지하며 로그인 화면에서는 숨긴다. 페이지별 사이드바와 루트 `loading.tsx`의 전체 화면 로딩은 제거했다. 경로를 준비하는 동안 현재 화면을 유지하고, 새 화면이 데이터를 기다리는 경우 본문에서만 로딩을 표시한다.

## 조회와 로딩

- `GET /api/v1/repairs?hospitalId=<id>`는 해당 병원의 기록만 반환한다. 병원 상세와 서비스 기록 상세의 이력 탐색에서 사용한다. 필터 없는 기존 조회는 호환성을 유지한다.
- 회의록·구성원 관리·서비스 기록 목록은 해당 화면을 열 때 코드를 불러온다. 메뉴 링크는 다음 화면을 미리 준비한다.
- 문서 뷰어에서 편집기 전체를 가져오지 않도록 HTML 변환 함수를 분리했다.
- 동일한 로컬 production 빌드의 `/page`와 `/layout` 자바스크립트 파일을 중복 없이 합산하고 gzip으로 비교했을 때 초기 파일 용량은 약 187 KiB → 162 KiB (약 13% 감소)였다. 실제 응답 시간은 네트워크·캐시·서버 상태에 따라 달라진다.
- 운영 DB 조회 시 전체 활성 서비스 기록은 218건, 정병원 기록은 13건이었다. 새 병원별 조회는 다른 병원의 기록 전송을 줄인다.

## 검증

프런트엔드 lint/typecheck/production build, 백엔드 테스트 45개를 통과했다. UI는 로컬 샘플 API로 대시보드·병원 검색·수리 작성·회의록과 모바일 390px/큰 글씨/다크 모드를 확인한다. 실제 운영 로그인 세션을 확보하지 못한 경우 로그인 후 운영 화면 검증과 구분해서 보고한다.

이번 변경에는 새 DB 스키마 또는 기존 기록의 이동이 없다.
