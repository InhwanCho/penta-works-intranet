# 세금계산서

회계 메뉴 `/accounting/tax-invoices`에서 일반 정발급 세금계산서와 면세 계산서를 작성한다. 기존 allbiz 클라이언트의 tax-invoice-new.tsx, tax-invoice-list.tsx, invoice-ui.tsx UI를 기준으로 문서 시트·세로 공급자 제목·색상·칸별 테두리·라디오 옵션·메모 위치·품목표 하단 합계행·발행 버튼을 이식했다. 공급자/공급받는자 입력은 28px, 행은 36px로 원본 규격을 유지하며 1536px부터 양쪽 그리드를 나란히 배치한다. Office의 인증·회계 권한·저장 및 발급 보호는 유지한다.

## 공급자

`017_tax_invoices.sql`은 남동구 소재 주식회사 펜타웍스의 사업자등록증 기본정보를 한 건 생성한다. 사업자번호는 기존 바로빌 연동 계정과 대조했다. 사용자 지정 기본 담당자는 조재영, 이메일은 jycho@pentaworks.net, 연락처·휴대폰은 01038998786이다. `018_invoice_issuer_contact.sql`이 기존 기본정보에도 한 번만 적용하며 문서별 공급자 스냅샷은 변경하지 않는다. 회계의 공급자 설정에서 **바로빌 정보 가져오기**를 누르면 최근 90일 매출 문서의 공급자 정보(있는 경우)와 현재 연동 계정의 담당자 정보를 읽는다. 명시적으로 저장한 담당자·연락처가 있으면 그 값을 우선 유지한다. 최근 매출이 없으면 저장된 사업자 기본정보를 유지한다. 다른 회사/남동구 외 주소는 자동 가져오지 않는다. 바로빌 연동 인증키는 서버 환경변수로만 사용한다.

공급자 설정은 낙관적 잠금으로 저장한다. 문서 저장 시 당시 공급자 정보를 스냅샷으로 보존하며 발급 후 변경하지 않는다. 작성 화면의 공급자는 기본적으로 잠겨 있고 ‘수정 → 적용’으로 해당 문서만 편집할 수 있다. 편집 취소 시 원래 값으로 돌아가며, 기존 문서를 다시 저장할 때도 저장된 공급자 스냅샷을 유지한다. 회사 기본정보는 목록의 공급자 설정에서 별도로 변경한다. 기존 장부와 거래 내역은 변경하지 않는다.

## 저장 및 발급

- 필수 품목·수량·단가·작성일·같은 달 공급일자를 서버에서 검증한다. 사업자번호는 체크섬으로 확인한다.
- 수량·단가는 소수점 4자리까지, 공급가액은 품목별 원 미만 버림, 과세 세액은 품목별 10% 버림이다. 서버는 BigDecimal, 화면은 고정소수점 BigInt로 계산한다.
- 임시저장은 요청 UUID로 재시도 중복을 막고 버전으로 동시 수정을 방지한다. 최근 문서의 거래처 전체 정보를 다음 작성에서 다시 선택할 수 있다.
- 발급 전 검토를 거쳐 저장된 버전을 한 번만 `DRAFT → SENDING`으로 원자적으로 변경한 뒤 DB 트랜잭션 밖에서 바로빌을 호출한다. 실제 발급은 사용자가 최종 버튼을 누를 때만 발생한다. SMS 및 지연발급 강제 옵션은 끈다.
- 성공 응답 1은 `ISSUED`, 음수 오류는 `FAILED`, 통신 실패·비정상 응답·중복 관리번호 오류는 `UNKNOWN`으로 남긴다. 발급 후에는 수정/재발급 버튼을 제공하지 않는다. 자동 재시도는 하지 않는다.
- 서버 종료 등으로 `SENDING`이 남아도 동일 관리번호로 **상태 조회**할 수 있다. 발급 당시 사업자번호/테스트·운영 환경이 일치해야 한다. 실제 발급일 응답을 확인한 경우에만 결과를 발급 완료로 복구한다.
- 발급 완료와 국세청 전송 상태/승인번호는 별도로 표시한다. 바로빌 원시 상태 코드를 함께 제공한다. 국세청의 정식 증빙 대신 자체 출력물을 오인하지 않도록 인쇄물에 안내한다.
- 수정발급·역발행·발급 취소 및 기존 바로빌 내역의 일괄 이관은 이번 구현에 포함하지 않는다. 원본의 미지원 발급 유형(바로빌 전송·수정·역발행)은 폼에 동일한 위치로 표시하되 선택을 비활성화한다. 제품 선택은 이전 문서에서 사용한 품목을 재사용하며 외부 제품 카탈로그는 연동하지 않는다. 연락처와 휴대폰은 별도로 저장한다.

회계와 관리자 역할만 API를 사용할 수 있고, 쓰기 요청에 기존 CSRF 보호를 적용한다. 공급자 변경·문서 저장·발급 요청·상태 조회는 감사 이력에 남는다. 인증키와 문서 전체 내용은 감사 로그에 저장하지 않는다.

## 배포 및 확인

운영 DB 백업 후 기존 deploy.sh가 `017_tax_invoices.sql`을 적용한다. 기존 스키마와 함께 반복 적용해도 문서를 덮어쓰지 않는다. 기본 공급자 담당자는 마이그레이션에서 설정하며, 회사 기본정보를 갱신할 때만 공급자 설정의 바로빌 정보 가져오기를 사용한다. 실제 세금계산서를 테스트용으로 운영 발급하지 않는다.

로컬 검증: `pnpm typecheck`, `pnpm lint`, `pnpm build`, Java 17 `./gradlew test`.
실제 MariaDB 회귀 검증은 별도 로컬 DB만 허용한다. 예: `ACCOUNTING_TEST_DB_URL=jdbc:mariadb://127.0.0.1:13329/mysql ./gradlew test`. 매 테스트에서 임시 DB를 만들고 삭제하며 발급 API는 mock을 사용한다. 운영 세금계산서 발급·메일 발송은 실행하지 않는다.

API 계약은 바로빌 공식 [발급 SOAP 스키마](https://ws.baroservice.com/ti.asmx?op=RegistAndIssueTaxInvoice), [상태 조회](https://ws.baroservice.com/ti.asmx?op=GetTaxInvoiceStateEX), [WSDL](https://ws.baroservice.com/ti.asmx?WSDL)을 따른다. allbiz의 프런트엔드 enum을 바로빌 SOAP enum으로 그대로 전달하지 않는다. 면세는 `TaxInvoiceType=2`, 그 외에는 `1`을 전달한다.
